# 🎮 SSAPI-Minecraft v2

SSAPI-Minecraft v2 는 숲(SOOP) 과 치지직의 후원·미션을 마인크래프트 서버 액션으로 연동하는 플러그인입니다.

> **v2.0 신규**: 한 후원에 여러 보상 실행, 금액 범위 조건, 인게임 관리 GUI, 도전·대결미션 처리, 동시송출 연동, 킷 보상

## 📋 소개

SSAPI 는 숲·치지직 후원·미션 데이터를 같은 형태로 정리해 주는 서비스입니다. 이 플러그인은 그 데이터를 받아 **후원 금액이나 미션 종류에 맞는 마인크래프트 보상**(아이템 지급, 몹 소환, 텔포, 효과, 커맨드 실행 등)을 실행합니다.

**누구에게 필요한가?**
- 시청자 후원에 따라 게임 안에서 이벤트를 발생시키고 싶은 스트리머
- 미션 정산 시점에 보상을 지급하고 싶은 서버 운영자
- 동시송출(SOOP + 치지직) 후원을 모두 받고 싶은 분

## 🚀 빠른 시작 (5분)

1. **API 키 발급** — https://ssapi.kr/app/applications/new
2. **플러그인 설치** — `plugins/` 폴더에 jar 복사 후 서버 시작
3. **API 키 입력** — `plugins/SSApi/config.yml` 의 `api.key` 에 발급받은 키 붙여넣기
4. **서버 재시작** (또는 `/API관리 리로드`)
5. **연동** — 인게임에서 `/API 연동 숲 streamer2022` (또는 `/API 연동 치지직 12c5af...`)
6. **시작** — `/API 시작`

테스트는 `/API테스트 1100` 으로 1,100원 후원을 시뮬레이션할 수 있습니다.

## 🧭 먼저 알아둘 용어

| 용어 | 뜻 |
|---|---|
| 스트리머 ID | 숲 방송국 아이디 또는 치지직 채널 ID 입니다. 마인크래프트 닉네임이 아닙니다. |
| 마크 아이디 | 마인크래프트 플레이어 닉네임입니다. 내부 저장에는 UUID도 함께 사용합니다. |
| 메인 연동 | 후원을 받을 기본 스트리머 채널 1개를 마크 계정과 연결하는 것입니다. |
| 동시송출 연동 | 메인 연동 외에 다른 플랫폼 채널을 하나 더 연결하는 것입니다. 예: 메인은 숲, 동시송출은 치지직. |
| 시작 / 중지 | 후원 보상 실행 여부를 로컬 파일에서 켜고 끄는 기능입니다. SSAPI 서버 등록을 삭제하지 않습니다. |
| 트리거 | “1,000원 이상 후원”, “미션 정산 완료”처럼 보상을 실행할 조건입니다. |
| 액션 | 조건이 맞았을 때 실제로 실행할 일입니다. 예: 커맨드 실행, 킷 지급, 몹 소환. |
| 킷 | 보상으로 지급할 아이템 묶음입니다. GUI에서 인벤토리처럼 편집할 수 있습니다. |
| JSONL 로그 | 한 줄에 JSON 객체 하나씩 쌓이는 로그 파일입니다. 텍스트 편집기나 로그 수집기가 읽기 쉽습니다. |

## 📜 명령어

대소문자 모두 인식 — `/api`, `/API`, `/API관리` 모두 동작.

### 사용자 명령어 — `/API`

```
/API 연동 <숲|치지직> <id>           — 메인 연동
/API 동시송출연동 <숲|치지직> <id>   — 동시송출 추가 연동 (다른 플랫폼만 가능)
/API 동시송출해제                    — 동시송출 연동만 해제
/API 시작                            — 후원 보상 받기 시작
/API 중지                            — 후원 보상 받기 중지
/API 상태                            — 내 연동 현황
```

`/API 시작` 과 `/API 중지` 는 SSAPI 서버의 등록 정보를 삭제하지 않습니다. 플러그인 폴더의 `connections.yml` 에 저장된 보상 실행 상태만 켜고 끕니다.

이미 연동한 상태에서 `/API 연동 <플랫폼> <새아이디>` 를 다시 실행하면 기존 메인 연동 해제를 먼저 시도하고, 새 아이디로 교체합니다. SSAPI 서버가 “이미 등록된 아이디”라고 응답하면 실제 등록은 된 상태로 보고 로컬 정보만 성공 상태로 맞춥니다.

### 관리자 명령어 — `/API관리` (`ssapi.admin` 권한)

```
/API관리                              — GUI 열기 (메인 메뉴)
/API관리 도움말 [페이지]              — 도움말
/API관리 상태                         — 시스템 / 미션 설정 상태
/API관리 리로드                       — 설정 다시 불러오기 (검증 실패 시 기존 설정 유지)
/API관리 저장                         — 메모리 상태 디스크에 flush
/API관리 디버그 <on|off>              — 디버그 로깅 토글

/API관리 시작 <플레이어>              — 다른 플레이어 보상 시작
/API관리 중지 <플레이어>              — 다른 플레이어 보상 중지
/API관리 연동 <플레이어> <숲|치지직> <id>  — 다른 플레이어 메인 연동
/API관리 동시송출연동 <플레이어> ...
/API관리 동시송출해제 <플레이어>
/API관리 연동정보삭제 <스트리머아이디|마크아이디>  — 잘못 등록된 연동 정보 강제 삭제

/API관리 킷 <목록|편집|지급|추가|삭제|이름>     — 킷 관리 (GUI 권장)
/API관리 트리거 <목록|토글>           — 트리거 관리 (GUI 권장)
/API관리 미션                         — 미션 설정 확인 (대시보드 링크)

/API관리 설정 <검증|복구|백업|원본>   — 설정 파일 관리
/API관리 확인 <토큰>                  — 파괴적 작업 확인
```

### 테스트 명령어 — `/API테스트` (`ssapi.command.test`)

```
/API테스트 <금액> [플레이어]                       — 테스트 후원 생성
/API테스트 미션 receive [금액] [플레이어]          — 미션 후원 수신 테스트
/API테스트 미션 settle [총금액] [후원자수] [플레이어]  — 미션 정산 테스트
/API테스트 미션 result [플레이어]                  — 미션 결과 테스트
```

테스트 명령어로 만든 후원·미션 데이터에는 `_test: true` 표시가 붙습니다. 운영 중 실제 후원과 구분해서 로그나 트리거 동작을 확인할 때 사용합니다.

## 🔄 후원이 들어왔을 때 무엇이 일어나나

```
SOOP/치지직 후원
       │
       ▼
SSAPI 서버 (숲/치지직 데이터를 같은 형식으로 정리)
       │
       ▼  Socket.IO 실시간 이벤트
플러그인 — DonationListener
       │
       ▼  보상 실행 상태 확인
       │
       ▼  조건에 맞는 트리거 찾기
매칭된 트리거의 actions 순차 실행
       │
       ├── command          (서버 명령어, lines 여러 줄 가능)
       ├── give_kit         (kits.yml 의 킷 지급)
       ├── spawn_mob        (랜덤 몹 소환)
       ├── random_effect    (랜덤 포션 효과)
       ├── random_teleport  (랜덤 위치)
       └── instant_death    (즉사)
```

한 트리거에는 여러 액션을 넣을 수 있습니다. 예를 들어 “5,000원 이상 후원”에 아이템 지급과 몹 소환을 동시에 실행할 수 있습니다.

### 기존 Skript 명령어로 넘기기

v1처럼 기존 Skript가 보상 분기를 이미 처리하고 있다면, `triggers.yml` 에서 모든 후원을 하나의 `command` 액션으로 넘기면 됩니다.

```yaml
donation:
  - id: legacy_skript_donation
    enabled: true
    match: { op: any }
    priority: 1000
    stop_on_match: true
    actions:
      - type: command
        lines:
          - "donation {player} {cnt} {donator_name}"
```

이렇게 하면 SSAPI 플러그인은 후원 데이터를 전달만 하고, `33`, `330`, `3330` 같은 세부 코드는 Skript의 `/donation` 명령어가 계속 판단합니다.

### 연동 직후 닉네임 설정

`connect:` 트리거는 `/API 연동` 이 성공했을 때 1회 실행됩니다. 숲/치지직 공개 채널 정보에서 채널 닉네임을 가져와 `{streamer_nickname}` 으로 넣고, 명령어에 안전하게 쓰기 좋게 정리한 값은 `{nickname}` 또는 `{streamer_nickname_safe}` 로 제공합니다.

```yaml
connect:
  - id: nickname_auto
    enabled: true
    match: { op: any }
    priority: 100
    stop_on_match: true
    actions:
      - type: command
        lines:
          - "nick {nickname} {player}"
```

연동/해제 REST 호출은 서버 메인 스레드를 막지 않도록 비동기로 처리하고, 실제 마인크래프트 명령어 실행만 서버 스레드에서 수행합니다.

## 🎯 미션 기능

도전미션(혼자 진행)·대결미션(스트리머 두 명 vs)·참가미션(다른 사람 미션에 합류)을 모두 지원.

### 보상을 실행할 시점

미션은 상황에 따라 여러 번 이벤트가 올 수 있습니다. 아래 시점 중 필요한 것만 켜서 보상을 실행합니다. 기본값은 정산 시점(`settle`)입니다.

- **receive** — 미션 후원이 들어올 때마다
- **settle** — 미션 정산 시점 (도전미션 종료 / 대결미션 결과 확정)
- **result** — 미션 결과 메타가 도착했을 때 (SUCCESS / FAILURE / DRAW)

### 정산 처리 방식 (config.yml)

`mission.settle_payout`:
- `combined` (기본) — 미션의 모든 후원 금액을 합쳐서 보상을 1회 실행
- `individual` — 후원자별로 보상을 여러 번 실행

### 동시 다중 미션

한 스트리머가 여러 미션을 동시에 진행해도 서로 섞이지 않도록 미션별로 따로 처리합니다.

## 🎁 킷 시스템

CMI 스타일의 킷 시스템 — 인벤토리 슬롯별로 아이템 묶음을 저장하고 트리거 액션으로 지급.

**가장 쉬운 방법**: `/API관리` GUI 에서 킷 메뉴 → 새 킷 → 인벤토리에 아이템 드래그 → 닫기 (자동 저장).

수동: `kits.yml` 파일이나 `/API관리 킷 추가 <이름>` 명령.

## 📁 설정 파일

| 파일 | 책임 | 자동 쓰기 | 주석 보존 |
|---|---|---|---|
| `config.yml` | API 키, 소켓, 스토리지, 미션 처리, 액션 옵션 | ❌ | ✅ |
| `triggers.yml` | 후원 / 연동 직후 트리거 | GUI 편집 시 | 헤더만 |
| `kits.yml` | 킷 (GUI 가 자동 관리) | 자주 | 헤더만 |
| `messages.yml` | 모든 채팅 / 알림 메시지 | ❌ | ✅ |
| `logs/*.jsonl` | API 호출/후원/미션 추적 로그(JSONL) | 자동 | N/A |

미션 보상 시점은 `config.yml` 의 `mission` 섹션에서 설정합니다. 메시지는 `messages.yml` 에서 자유롭게 바꿀 수 있으며, MiniMessage 문법을 사용할 수 있습니다.

### 로그 파일

`logs` 폴더에는 운영 확인용 로그가 날짜별 JSONL 파일로 쌓입니다.

| 파일 | 내용 |
|---|---|
| `api-calls-YYYY-MM-DD.jsonl` | SSAPI REST API 요청, 응답, 소요 시간, 오류 코드 |
| `donations-YYYY-MM-DD.jsonl` | 후원 이벤트 처리 결과 |
| `missions-YYYY-MM-DD.jsonl` | 미션 이벤트 처리 결과 |

JSONL은 한 줄이 JSON 객체 하나입니다. 파일 전체가 JSON 배열은 아니므로, 로그 수집기나 `tail` 같은 도구로 이어서 보기 좋습니다.

### 빠른 경로

| 작업 | 위치 |
|---|---|
| API 키 변경 | `config.yml` 의 `api.key` |
| 후원 금액별 액션 추가 | `/API관리` GUI → 트리거 |
| 킷 만들기 | `/API관리` GUI → 킷 |
| 메시지 색깔 변경 | `messages.yml` (MiniMessage 포맷) |
| 메시지 표시 안 하기 | `messages.yml` 의 해당 키를 빈 문자열 `""` 로 |
| 사운드 끄기 | `config.yml` 의 `sounds.<type>: false` |
| 보상 수신 시작/중지 상태 | `/API 시작`, `/API 중지` 또는 `connections.yml` |
| API 호출 원문 확인 | `logs/api-calls-YYYY-MM-DD.jsonl` |
| 후원/미션 처리 로그 확인 | `logs/donations-YYYY-MM-DD.jsonl`, `logs/missions-YYYY-MM-DD.jsonl` |
| 잘못 등록된 연동 강제 삭제 | `/API관리 연동정보삭제 <스트리머아이디|마크아이디>` |
| 설정 검증 | `/API관리 설정 검증` |
| 주석 복구 | `/API관리 설정 복구 <파일명>` |

## ❓ 자주 묻는 질문 (FAQ)

**Q. 동시송출인데 두 플랫폼 모두 받고 싶어요.**
먼저 `/API 연동` 으로 메인 연동 → `/API 동시송출연동` 으로 다른 플랫폼 추가. 같은 플랫폼은 등록 불가.

**Q. `/API 중지` 를 하면 SSAPI 서버에서도 연결이 끊기나요?**
아니요. `/API 중지` 는 이 플러그인 안에서만 보상 실행을 멈춥니다. SSAPI 서버 등록을 삭제하려면 관리자 대시보드나 `/API관리 연동정보삭제` 를 사용합니다.

**Q. 후원 메시지가 너무 시끄러워요.**
`messages.yml` 에서 해당 키를 빈 문자열로 설정. 사운드는 `config.yml` 의 `sounds.donation: false`.

**Q. 메시지 색이나 꾸밈을 바꾸고 싶어요.**
[MiniMessage 가이드](https://docs.advntr.dev/minimessage/format.html) 참고. 예: `<red>빨간 글씨</red>`, `<click:run_command:'/foo'>[클릭]</click>`.

**Q. 오프라인 플레이어에게도 보상을 지급하고 싶어요.**
`config.yml` 의 `reward.execute_when_offline: true`. 단, 인벤토리 의존 액션(`give_kit`, `random_teleport`, `instant_death`)은 자연 실패 — `command` 액션만 의미 있음. EssentialsX `mail send` 같은 우편함 플러그인이 있을 때만 권장.

**Q. 오류가 나는데 원인을 모르겠어요.**
`/API관리 디버그 on` → 콘솔 로그 확인. REST API 호출 기록은 `logs/api-calls-YYYY-MM-DD.jsonl` 에 한 줄당 JSON 객체 1개로 저장됩니다. 설정 검증은 `/API관리 설정 검증`.

**Q. 실수로 다른 아이디에 연동했거나 API 서버와 로컬 상태가 어긋났어요.**
같은 플레이어가 `/API 연동 <플랫폼> <새아이디>` 를 다시 실행하면 기존 메인 연동을 해제한 뒤 새 아이디로 교체합니다. 관리자는 `/API관리 연동정보삭제 <스트리머아이디|마크아이디>` 로 특정 연동 정보를 강제로 삭제할 수 있습니다.
